Executive Overview

Abstract

Conventional student productivity software—spanning simple To-Do checklists, Kanban boards, and standard calendars—exhibits a fundamental structural flaw: it models task management as an unconstrained list of deliverables governed by a single Submission Due Date. This architectural oversight produces the Due-Date Illusion: because deadlines are clustered at the end of academic cycles (e.g., Friday 11:59 PM or examination weeks), students perceive intervening days as free, leading to cognitive fatigue, acute panic, and deadline failure.

DeadlineDeck introduces an academic workload planning system engineered to counteract academic procrastination and burnout. Anchored by a Dual-Date Temporal Model and an automated Bounded Capacity Telemetry Engine, DeadlineDeck decouples the moment of submission from the allocation of cognitive effort. The platform continuously monitors academic commitments against a student's configured daily study thresholds, computing exact mathematical workload utilization metrics (Utilization %).

The platform features a signature Weekly Workload Map equipped with vertical cylinder pill gauges and visual coral diagonal hatch overflow textures. Constructed strictly adhering to a high-performance Vanilla Web Architecture (zero external framework bloat, sub-120KB total client bundle), DeadlineDeck is powered by an Express.js (Node.js) server, a Third Normal Form (3NF) MySQL 8.0 relational database, and comprehensive session management. The system has achieved 100% test passing across 30 automated test cases and zero layout overflows across 17 responsive web routes audited via headless Chrome DevTools Protocol.

Core Innovation: Traditional tools record what is due. DeadlineDeck computes whether the workload is physically feasible within the student's available hours before deadlines turn into academic emergencies.
Chapter 1

Introduction & Motivation

1.1 Background

Engineering curricula subject students to intense, concurrent academic workloads. In any standard semester, an undergraduate Computer Science student typically undertakes five to seven courses simultaneously. Each course operates semi-autonomously, assigning homework, laboratory programming reports, semester team projects, continuous assessment quizzes, and terminal examinations.

Because departmental instructors assign deadlines independently, academic pressures frequently collide on identical dates. Students without predictive workload tools fall victim to task clustering, sleep deprivation, and severe quality degradation in academic submissions.

1.2 The Problem with Existing Task Tools

  • Generic To-Do Lists (Todoist, Microsoft To Do, Apple Reminders): Rely on binary checklists. They permit infinite tasks to be added to a single day with zero consideration of how many hours exist in that day, inevitably resulting in task bankruptcy.
  • Digital Calendar Blocking (Google Calendar, Microsoft Outlook): Demands tedious manual time-blocking. When an unexpected lab or class delay occurs, the entire calendar schedule breaks, requiring painful manual reorganization.
  • Project Management Suites (Trello, Jira, Asana): Designed for asynchronous corporate teams. They lack native student constructs such as course codes, grade credits, examination categories, and daily study hour limits.

1.3 Project Objectives

  1. Dual-Date Scheduling: Separate the Submission Due Date from the Planned Study Date to distribute work evenly.
  2. Continuous Workload Telemetry: Mathematically compute daily pressure and categorize days into Balanced, Near Capacity, and Overloaded states.
  3. Visual Signature Instrument: Provide an intuitive 7-day Weekly Workload Map with responsive vertical cylinder gauges and diagonal hatch patterns.
  4. Algorithmic Priority Dispatching: Implement a heuristic ranking engine for the student's daily focus that escalates overdue and high-weight tasks.
  5. Unified Academic Toolkit: Provide native academic utilities including Pomodoro timers, marks calculators, citation generators, and rubric checklists.

2.1 The Due-Date Illusion Mathematical Proof

Consider three academic assignments A1, A2, A3, each requiring 2.5 hours of study effort (Total Required = 7.5 hours). All three have a submission deadline on Friday at 23:59.

  • In a Generic To-Do App: Monday through Thursday show zero tasks. Friday lists three tasks. The student assumes Monday–Thursday are free. On Friday evening, available study time is only 3 hours. The deficit is 4.5 hours, creating an irrecoverable deadline failure.
  • In DeadlineDeck: The student plans A1 for Tuesday (2.5h), A2 for Wednesday (2.5h), and A3 for Thursday (2.5h). The platform calculates Tuesday (83.3%), Wednesday (83.3%), Thursday (83.3%), and Friday (0%), entirely preventing overload.

Chapter 4

Mathematical Formulations & Telemetry Models

4.1 Workload Pressure Telemetry Formula

Let U be the authenticated student and D be the target date in the 7-day planning window. The set of active, uncompleted academic deliverables allocated to D is defined as:

ActiveTasks(U, D) = { t in Tasks(U) | t.planned_date = D and t.status != 'Completed' }
TotalWorkloadHours(U, D) = Sum of estimated_hours for all t in ActiveTasks(U, D)

The available capacity Cap(U, D) resolves with precedence given to explicit date overrides:

Cap(U, D) = Override(U, D) if configured in study_capacity, else U.default_study_hours

4.2 Utilization Percentage & Threshold Policies

Utilization(U, D) = (TotalWorkloadHours / AvailableCapacity) * 100%
(Safe zero capacity handling prevents division by zero)

Implementation Modules & User Experience

5.1 The Signature Weekly Workload Map

The core visual instrument of DeadlineDeck is the 7-day horizontal Workload Map:

  • Responsive Day Cards: Displays Day of week, Calendar date, and an active "TODAY" badge on the current day.
  • Vertical Capacity Cylinder Gauges: Styled with rounded-full pill tracks (border-radius: 9999px) with an inner drop shadow. A bold horizontal tick line marks the exact daily capacity limit.
  • Diagonal Hatch Overflow Pattern: Hours exceeding 100% capacity render with a dynamic CSS diagonal repeating hatch pattern, immediately signaling pressure to the student.
  • Interactive Schedule Shelf: Clicking any day card opens that day's scheduled deliverables in an executive drawer below, complete with duration pills, priority badges, and an instant "+ Add Task for This Day" action.

5.2 Academic Productivity Toolkit

  1. Study Session Planner & Pomodoro Timer: 25-minute focused study cycles with 5-minute restorative breaks. Directly tracks and logs completed minutes to the database.
  2. Academic Marks & Percentage Calculator: Calculates internal test weights, semester SGPA, and required marks to achieve target grades.
  3. Scholarly Citation Generator: Formats bibliographic citations into IEEE, APA, MLA, and Harvard standards with one-click clipboard copying.
  4. Assignment Checklist Builder: Breaks complex deliverables (e.g., Capstone B.Tech project) into hierarchical sub-milestones with automated progress tracking.
  5. Quick Notes Repository: Persistent student scratchpad for formula cheatsheets, faculty office hours, and assignment rubrics.

Chapter 7

Production Deployment & DevOps

7.1 Production Security Hardening

  • Reverse Proxy Readiness: app.set('trust proxy', 1) enables secure session cookies over HTTPS when running behind Nginx, Render, Railway, or Cloudflare.
  • Zero Server Fingerprinting: app.disable('x-powered-by') strips the Express banner to prevent framework targeting.
  • HTTP Security Headers: Every HTTP response injects X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, Referrer-Policy: strict-origin-when-cross-origin, and X-XSS-Protection.
  • Graceful Shutdown: Signal traps for SIGTERM and SIGINT cleanly drain open requests and close the MySQL connection pool before container exit.

Conclusion & Future Scope

8.1 Conclusion

The DeadlineDeck academic project successfully addresses the root structural flaw of modern student productivity tools. By replacing static checklist mechanics with a Dual-Date Temporal Model and Bounded Capacity Telemetry, the platform empowers students with mathematical visibility into future bottlenecks. The platform fulfills all software engineering standards, achieving sub-second API latencies, 100% automated test coverage, and a modern, responsive user experience without third-party framework bloat.

8.2 Future Scope

  1. Learning Management System (LMS) Integration: Native two-way synchronization with Canvas, Moodle, and Google Classroom APIs to automatically ingest syllabus deadlines.

  3. Automated Academic Morning Digest: Integration with Telegram or WhatsApp Bot APIs to deliver a daily 8:00 AM briefing detailing scheduled hours, upcoming milestones, and capacity warnings.
